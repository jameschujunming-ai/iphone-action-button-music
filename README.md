# iPhone 操作按钮两秒切歌

用 iPhone 左侧的操作按钮，在两次长按之间选择下一首或上一首。想少看一眼手机屏幕、专心听歌，这是一个可以尝试的快捷指令。

**每次切歌需要两次长按：第一次开始计时，第二次启动间隔 ≤ 2 秒切下一首，> 2 秒切上一首。** 音量仍由原生音量键控制；本指令不包含播放/暂停。

## 下载与安装

**[下载可导入的快捷指令](操作按钮两秒切歌.shortcut?raw=true)**

1. 在 iPhone 的 Safari 中打开本页，下载上面的 `.shortcut` 文件。若看到 GitHub 文件页面，点 **Download raw file / 下载原始文件**。不要下载名称带 `.source` 的源码文件。
2. 从 Safari 的下载列表或“文件”App 打开下载文件，在“快捷指令”中点“添加快捷指令”。GitHub 仓库页面本身不是 iCloud 一键添加链接。
3. 进入 **设置 → 操作按钮 → 快捷指令 → 选择快捷指令 → 操作按钮两秒切歌**。
4. 首次先在解锁状态运行；如果系统请求读写计时文件的权限，请允许。先用音乐 App 播放一首歌并准备好播放队列。
5. 按下面的两次长按方式测试。首次授权花的时间不适合用来判断两秒手感。

也可以在 Mac 下载后，通过隔空投送把 `.shortcut` 文件发到 iPhone。接收方不需要使用与制作者相同的 Apple ID；首次读写权限需要在接收设备上允许。

### 设备要求

- iPhone 本身具有**左侧操作按钮**，且可以将它绑定到快捷指令。这里不是右侧锁屏/电源按钮，也不是音量键。
- 已安装苹果“快捷指令”，可访问 iCloud Drive 中的 `Shortcuts` 文件夹。
- 音乐 App 支持系统的上一首/下一首媒体命令，并且有可切换的播放队列。本项目面向 Apple Music、网易云的听歌场景，其他 App 需要自行测试。
- 不需要开发者模式、Xcode、越狱或额外第三方 App；普通使用者也不需要运行本仓库的 Python 源码。

## 怎么操作

| 步骤 | 做什么 | 结果 |
| --- | --- | --- |
| 第一次 | 长按左侧操作按钮，指令启动后松开 | 记录时间，音乐保持原样 |
| 想下一首 | 尽快再次长按，使两次指令启动间隔不超过 2 秒 | 下一首 |
| 想上一首 | 停顿久一点，再次长按，使间隔超过 2 秒 | 上一首 |
| 已完成一次切歌 | 再长按开始下一组 | 重新计时 |

计时从**第一次快捷指令启动**到**第二次快捷指令启动**，不是从手指松开开始，也不是判断单次按住了几秒。它不把操作按钮改成单击/双击按键。

第一次只保存时间并立即结束，没有“等待两秒”的运行步骤。第二次才能决定切歌方向。系统长按识别、指令启动和文件读写都有耗时，请先熟悉自己手机上的节奏，避免刻意卡在两秒边界。

**没有超时自动取消。** 如果只完成第一次，隔很久才再按，下一次仍按“第二次”处理，会执行上一首。若想取消这个待处理状态，在“文件 → iCloud Drive → Shortcuts”中删除 `ActionMusicInterval.txt`；下次运行会重新开始计时。不要删除整个 `Shortcuts` 文件夹。

## 提示、音量与播放暂停

- 正常运行不主动显示数字、结果弹窗或选择菜单；系统自己的快捷指令运行提示可能仍会出现。
- 第一次读写文件可能出现系统权限请求；权限未允许或文件服务异常时，系统也可能显示错误。
- 不读取或修改音量；音量加减键仍保留原来的功能。
- 本指令只切上一首、下一首。播放/暂停可以继续使用耳机已有的触控或线控操作。

## 使用状态与已知限制

当前是 **v0.1.0 试用版**，截至 2026-10-23：

- 使用者在手机试用后反馈“基本没啥问题”。这是实际反馈，尚没有覆盖所有 App、系统版本和使用状态的测试矩阵。
- Mac 上真实“快捷指令”运行验证了短间隔下一首、长间隔上一首、切歌后清除状态，以及连续成组处理。诊断版将媒体动作替换成分支记录，用于检查判断逻辑。
- 不含诊断记录的版本曾测得两次运行约 1.1 秒与 0.8 秒；测试过程中也曾出现明显延迟和超时。不能据此承诺每台手机都能稳定满足两秒节奏。
- 本版的真机熄屏触发、精确 2.000 秒边界及不同 App 行为没有逐项完成独立验证。**不要将手机上“基本能用”理解为所有熄屏场景均已通过。**

其他需要知道的限制：

- 快捷指令运行尚未结束时再次按操作按钮，可能无法启动下一次；系统调度和文件服务会影响手感。
- 计时文件保存在 iCloud Drive。相同 Apple ID 的多个设备若同时运行这条指令，可能共享或覆盖状态；当前没有设备隔离或并发锁，建议一次只在一台设备使用。
- “上一首”先定位到当前曲目的 0 秒，再发送后退命令，以减少只回到当前曲目开头的情况。播放器、网络电台或不同队列仍可能有不同表现。
- 文件权限、下载状态、iCloud Drive 是否可用，都会影响执行。本版没有自定义报错弹窗。

## 常见问题

**按一次没有反应？** 这是设计行为。第一次只开始计时，第二次才切歌。先确认绑定的是本指令，以及你用的是长按。

**明明想下一首，却到了上一首？** 两次指令实际启动间隔可能超过了两秒。第一次启动后松开并尽快再次长按；如果刚刚只按过一次，也可能还留着上一次计时状态。

**没有切歌，但计时已经清除了？** 本版在媒体动作前清除计时，避免下一次重复执行旧操作。检查音乐 App 是否正在播放、有无下一首/上一首，以及是否支持系统媒体命令，然后重新开始一组。

**下载后打不开，或者跑进快捷指令中心？** 确认下载的是 `.shortcut` 文件，而不是网页、`.source.shortcut` 或整个仓库 ZIP。用“文件”App 打开文件，再添加；可尝试从 Mac 隔空投送同一个文件。

**能保证完全熄屏使用吗？** 这正是本项目的目标场景，但当前验证不足以对所有设备作出保证。先完成首次授权，再在自己的手机上分别测试亮屏与熄屏；出现问题时请注明系统版本、音乐 App 和具体操作。

## 数据与实现

指令读取当前时间，并在 `iCloud Drive/Shortcuts/ActionMusicInterval.txt` 保存一个时间戳；一组操作消费后写入 `idle`。没有读取歌曲库、联系人或位置，也没有第三方网络请求。这个文件可能随 iCloud 同步，并非严格只保存在本机。

仓库只包含可分享的指令、可读源码和构建/检查脚本。开发时的设备标识、本地音乐、个人聊天和调试记录不在发布内容中。

## 从源码构建

普通使用者直接下载上方已签名文件即可。开发者需要 Python 3；签名还需要带有 `shortcuts` 命令的 macOS。

```bash
# 生成可读 plist 源文件，不签名；输出到 build/
python3 build_shortcut.py --unsigned

# 生成源文件并调用苹果 shortcuts sign，输出到 build/
python3 build_shortcut.py

# 运行发布内容与源码一致性检查
python3 -m unittest test_release -v
```

生成文件默认写入 `build/`，不会覆盖已发布的下载文件。重新签名后须重新导入测试；签名成功不等于实际功能已经验证。

开发诊断模式：`python3 build_shortcut.py --diagnostic`。它不切歌，使用独立的 `ActionMusicInterval-test.txt` 状态文件和 `ActionMusicInterval-result.txt` 分支记录；不要将诊断版绑定为日常切歌指令。
